## 3. Docker Containers

- Container lifecycle
- Detached and interactive execution
- Ports and test configuration

| Command | Purpose |
| --- | --- |
| `docker run --name test-app -d -p 8080:80 nginx` | Start a web container accessible on host port 8080 |
| `docker run --rm playwright-tests:1.0` | Run tests and remove the container after it exits |

| `docker rm <container>` | Remove a stopped container |

## 4. Docker Volumes and Bind Mounts

- Named volumes for database test data
- Bind mounts for test inputs and reports
- Keeping files after a container is removed

| Command | Purpose |
| --- | --- |
| `docker volume create test-data` | Create a named volume |
| `docker volume ls` | List volumes |
| `docker volume inspect test-data` | View volume details |
| `docker run --rm -v test-data:/data playwright-tests:1.0` | Mount a named volume at `/data` |
| `docker run --rm -v "$(pwd)/reports:/app/reports" playwright-tests:1.0` | Save reports in a local folder, using a macOS/Linux shell |
| `docker volume rm test-data` | Delete an unused volume and its stored data |

## 5. Docker Networks

- Connecting test runners, applications, and databases

- Understanding `localhost` inside a container

| Command | Purpose |
| --- | --- |

## 6. Dockerfile

- Creating an image for a Playwright Test project (JavaScript/TypeScript)
- Installing dependencies and defining the test command
- Using `.dockerignore` to exclude unnecessary files

| Instruction | Purpose |
| --- | --- |
| `FROM` | Select the base image |
| `WORKDIR` | Set the working directory |
| `COPY` | Copy test code and dependency files |
| `ADD` | Copy files with additional support for local archive extraction and remote sources; use `COPY` for ordinary file copying |
| `RUN` | Install dependencies during the build |
| `ENV` | Set default environment variables |
| `ARG` | Define build-time variables, such as a dependency version; avoid using them for secrets |
| `CMD` | Define the default command, such as running tests |
| `ENTRYPOINT` | Define the container executable; combine with `CMD` for default arguments |
| `EXPOSE` | Document the port an application uses; publish it separately with `docker run -p` |
| `USER` | Select the user for subsequent `RUN` instructions and the container process |
| `VOLUME` | Declare a container directory as a volume mount point; use runtime mounts to choose where reports are stored |
| `LABEL` | Add image metadata, such as the project name or test framework |
| `HEALTHCHECK` | Define a command to check whether a running service is healthy |
| `SHELL` | Set the shell used by subsequent shell-form instructions |
| `STOPSIGNAL` | Set the signal sent to the container process when stopping it |

### Dockerfile Practice Topics

- Understand build-time instructions versus container startup instructions.
- Compare `COPY` and `ADD`.
- Compare `ARG` and `ENV`.
- Combine `ENTRYPOINT` and `CMD` to run a test runner with configurable arguments.
- Use exec-form commands, such as `CMD ["npx", "playwright", "test"]`.
- Copy dependency files before test code to reuse cached dependency installation.
- Run tests as a non-root user and ensure report folders are writable.
- Add a health check to the application image used by the tests.

## 7. Docker Compose

- Defining application, database, and test runner services in `compose.yaml`
- Configuring ports, environment variables, volumes, and networks
- Connecting through service names
- Waiting for application readiness before testing

| Command | Purpose |
| --- | --- |
| `docker compose config` | Validate and view the resolved configuration |
| `docker compose up -d` | Start services in the background |
| `docker compose up -d --build` | Build images and start services |
| `docker compose ps` | View service status |
| `docker compose logs -f` | Follow service logs |
| `docker compose run --rm tests` | Run the service named `tests` as a one-off test runner |
| `docker compose down` | Stop and remove service containers and Compose networks |
| `docker compose down -v` | Also delete Compose-managed volumes and their test data |

## 8. Docker Logs and Troubleshooting

- Investigating failed test runs
- Checking container configuration and exit codes
- Collecting reports and monitoring resource usage

| Command | Purpose |
| --- | --- |
| `docker logs <container>` | Read container output |
| `docker logs -f <container>` | Follow live output |
| `docker logs --tail 100 <container>` | Read the latest 100 log lines |
| `docker inspect <container>` | View container configuration and state |
| `docker inspect --format '{{.State.ExitCode}}' <container>` | Check the exit code of a stopped container that has not been removed |
| `docker cp <container>:/app/reports ./reports` | Copy reports from a container that has not been removed |
| `docker stats` | View container resource usage |
| `docker system df` | Check Docker disk usage |

## 1. Installation and Execution

| Command | Purpose |
| --- | --- |
| `npm init playwright@latest` | Create a Playwright project |

### 5.7 Date, Time, and Calendar Controls

## 21. Playwright Configuration File — Brief Overview

**File:** `playwright.config.ts`. Use `defineConfig()` to configure how tests are discovered, executed, and reported.

| Setting | Purpose |
| --- | --- |
| `testDir` | Set the test folder |
| `timeout` / `expect.timeout` | Set test and assertion timeouts |
| `retries` / `workers` | Control retries and parallel execution |
| `use.baseURL` | Set the target application URL |
| `use.headless` | Choose headed or headless execution |
| `use.trace` / `use.video` / `use.screenshot` | Configure diagnostics |
| `projects` | Define browser or suite configurations |
| `reporter` | Select report formats |
| `outputDir` | Choose the test artifact folder |
| `webServer` | Start and wait for a local application |

```ts
import { defineConfig } from '@playwright/test';

export default defineConfig({
  testDir: './tests',
  timeout: 30_000,
  expect: { timeout: 5_000 },
  retries: process.env.CI ? 1 : 0,
  reporter: [['list'], ['html', { open: 'never' }]],
  use: {
    baseURL: process.env.BASE_URL || 'http://localhost:3000',
    headless: true,
    trace: 'retain-on-failure',
    screenshot: 'only-on-failure',
    video: 'retain-on-failure',
  },
});
```

The application must already be available at the configured URL, or be started through `webServer`. For projects with both UI and API tests, use project test filters to avoid running API tests once per browser.

Reference: [Playwright use options](https://playwright.dev/docs/test-use-options).
